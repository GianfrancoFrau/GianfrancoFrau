## 🔴 Critical

### <a id="cr-1"></a>[CR-1] Netlify builds with Node 20, Astro 6 requires >= 22.12

- **File:** `netlify.toml` (line 6, `NODE_VERSION = "20"`)
- **Issue:** `astro@6` declares `engines.node >= 22.12.0`. Netlify will build this branch on Node 20, so
  the deploy is expected to fail (or run on an unsupported runtime). Pre-existing, but it blocks shipping
  any of these changes.
- **Suggested fix:**

```toml
[build.environment]
  NODE_VERSION = "22"
```

## 🟡 Medium

### <a id="md-1"></a>[MD-1] Project card looks fully clickable, only the title is a link

- **File:** `src/components/ProjectCard.astro` (the `<article>` and the `<h3>` link)
- **Issue:** The whole card reacts on hover (left border darkens), which signals a clickable block, but
  only the title text navigates to `/projects/<id>`. Clicking the description does nothing. Fix with a
  stretched link: `relative` on the article, `after:absolute after:inset-0` on the title link, and
  `relative z-10` on the `ProjectLinks` wrapper so the external buttons stay clickable.

### <a id="md-2"></a>[MD-2] No lockfile and no `.npmrc`, dependencies pinned to `latest`

- **File:** project root, `package.json`
- **Issue:** There is no `package-lock.json` and no `.npmrc` with `package-lock=true`, while several
  dependencies use `latest` (`@astrojs/vue`, `@astrojs/mdx`, `@astrojs/sitemap`, `@tailwindcss/typography`).
  Every Netlify build can resolve different versions than the local one. Pre-existing.

### <a id="md-3"></a>[MD-3] `npm audit` reports critical/high advisories, Astro fix needs a major upgrade

- **File:** `package.json`, `package-lock.json`
- **Issue:** Surfaced once the lockfile existed (MD-2). `npm audit --omit=dev` flags `astro <=7.2.7` as
  critical and several transitive packages (`devalue`, `postcss`, `nanoid`, `@vue/server-renderer`, …) as
  high. The output is fully static, so most of these only affect the build/dev server, not visitors; still,
  the Astro fix requires moving to Astro 7, a breaking upgrade that deserves its own branch.

## 🔵 Low

- **File:** `src/layouts/ProjectLayout.astro`
- **Suggestion:** The `BaseLayout` + header + `<main>` + footer wrapper is copied from `PageLayout`
  (and `BlogLayout` already does the same). Wrap the article in
  `<PageLayout title={title} description={description}>` so the container classes live in one place.

### <a id="lw-2"></a>[LW-2] Project pages repeat the card and render an empty prose block

- **File:** `src/layouts/ProjectLayout.astro`, `src/content/projects/*.md`
- **Suggestion:** All three project files have no body, so each page shows exactly what the card already
  shows, plus an empty `.prose` div. Either write a body for each project before publishing, or keep the
  pages out of the build (and the card link plain) until they have content.

### <a id="lw-3"></a>[LW-3] Copy: repeated "work" and inconsistent role descriptions

  platform and its APIs" reads better. The default meta description still says "Full Stack Developer",

### <a id="lw-4"></a>[LW-4] `nara.md` still carries the old Ischis description
